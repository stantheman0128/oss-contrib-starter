# 選題：方向、moat、檢查清單

你的環境預設是 **macOS + 繁體中文**。這與「Windows + cp950」是**不同的特化**，請建立**你自己能穩定重現**的優勢，不要去擠別人的 Windows 票。

---

## 1. 選 repo 的梯子（由上往下）

1. **你每天在用的工具**（最高可信度）  
2. **你熟悉生態的專案**（前端／後端／AI coding／設計系統…依你而定）  
3. 文件寫明歡迎貢獻、且最近外部 PR 有在 merge 的專案  
4. 避開：外部 PR 躺數月無人看、或維護者習慣自己重寫不合併的專案  

開碼前讀：`CONTRIBUTING*`、PR template、有無「禁止 AI／LLM」條款。

---

## 2. macOS + 繁中：你可以找的題型（示例）

這些是**方向**，不是指定 repo：

| 方向 | 為什麼你可能比別人適合 |
|---|---|
| 繁中／i18n 文案、locale、繁簡邊界 | 你看得懂「哪裡怪」 |
| 只在 Mac 爆的路徑、權限、書籤、沙盒 | Linux CI 綠、你本機紅 |
| Homebrew／Apple Silicon 假設錯誤 | 文件寫死 Intel 或錯誤 bottle |
| 檔名大小寫、NFC／NFD 檔名 | macOS 預設磁碟與 Git／Linux CI 行為差 |
| 開發者工具在「非英文系統」的錯誤訊息／編碼 | 你能貼真實截圖與 locale |
| 跨平台腳本把 `/` `\` 或 `open` vs `xdg-open` 寫死 | 你雙邊或至少 Mac 能證偽 |

**不要做的選題：**

- 熱門 `good-first-issue` 已堆三支 PR  
- 你無法重現、只能「看 code 猜」  
- 純改 README 表情符號卻想拿來當福利計畫主打  
- 跟風去擠同一個爆紅 AI 專案的同一條 issue（紅海）

## 3. 票的大小（建議組合）

| 級別 | 例子 | 建議 |
|---|---|---|
| **S** | 明確小 bug、文件、已有測試 | 只做「被邀請／help wanted／維護者點名」的；自己去掃一堆 S 容易像刷量 |
| **M** | 多檔、要 repro、有相鄰失敗 | **預設主食** |
| **L** | 狀態機、race、長時間 live repro | 一次做一題；Evidence 要完整 |

經驗比例參考：多數時間在 **M**，穿插少量 L；S 當調劑且要「被邀請」。

---

## 4. 開碼前檢查清單（複製到 claim／筆記）

把 issue 描述的每一個特徵列出來，問：我的根因假說能否解釋**每一條**？

- [ ] 在預設分支 **HEAD** 重現成功（步驟／指令已記下）  
- [ ] `gh pr list`／搜尋：無覆蓋中的 PR  
- [ ] 作者不是「剛開 issue 準備自己修」的活躍 maintainer（小心搶修）  
- [ ] 假說能解釋：間歇？只有某環境？相鄰功能是否也壞？  
- [ ] 修完後的「相鄰失敗」想過沒有（重開、切 session、空列表…）  
- [ ] 專案 AI 政策允許  

任一條「不能解釋」→ 換假說或換題。

---

## 5. 加深 vs 散開

同一間 repo：

1. 先 merge 第 1 支（證明你會玩）  
2. 再在**同一 subsystem** 做第 2、第 3 支  
3. 該 repo 已有未回的人類 review → **先回完**再開新的  
4. 同時 open 建議 ≤ 2–3  

「每個熱門專案丟一支」看起來像 spam，也不利申請敘事（敘事要的是**一小叢連貫貢獻**）。

```text
請依 docs/SELECT-TICKETS.md 幫我找 2–3 個候選。

排除：已有覆蓋 PR、good-first-issue 紅海、我無法重現的題。
gh 搜尋請串行。先列候選與風險，不要寫碼。
```
